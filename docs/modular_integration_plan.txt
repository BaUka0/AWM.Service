# Подробный модульный план интеграции AWM.Service + AWMService.Frontend

## Summary
Этот документ расширяет исходные планы интеграции и покрывает оба проекта:

- Backend: `AWM.Service`
- Frontend: `AWMService.Frontend`
- Активные frontend-приложения: `apps/student`, `apps/universal`, `apps/department`, `apps/admin`
- `apps/legacy` не интегрируется в первом проходе; использовать только как справочный материал при необходимости.

План разбит на 24 мелких этапа. Каждый этап фиксирует тему проблемы, файлы и их проблемы, а также решение.

## Public API / Contract Changes
- Добавить единый frontend API слой в `@awm/shared`: `apiClient`, auth storage, request/response interceptors, React Query provider.
- На backend оставить v1 endpoints, но добавить UI-enriched поля в DTO без резкого удаления старых `TitleRu/TitleKz/TitleEn`.
- Принять публичный формат локализации `{ ru, kk, en }`; backend `Kz` маппить в frontend/public `kk`.
- Добавить недостающие admin endpoints для users/roles, потому что frontend admin сейчас работает через `localStorage`, а backend имеет только `Auth` и `Users/me`.
- Добавить агрегирующие read endpoints там, где UI показывает карточку процесса целиком: `works/my-progress`, enriched topics/applications, enriched defense/pre-defense schedule.

**Тема проблемы:** два текущих плана дублируют идеи, но не дают исполнителю детальной карты.

**Файлы и их проблемы:**
- `AWM.Service/docs/integration_plan.txt`: слишком общий, больше похож на концепцию.
- `AWM.Service/docs/modular_integration_plan.txt`: покрывает только несколько work packages и не раскрывает весь frontend/backend scope.

**Решение:**
- `integration_plan.txt` хранит краткую дорожную карту.
- `modular_integration_plan.txt` становится основным рабочим документом с этапами, файлами, проблемами и решениями.

## Этап 2. Dev Bridge [DONE]
**Тема проблемы:** frontend-приложения работают на портах `3001-3004`, а backend CORS разрешает только `5173` и `3000`.

**Файлы и их проблемы:**
- `AWM.Service/src/AWM.Service.WebAPI/Program.cs`: CORS policy `AllowFrontend` не покрывает активные Vite ports.
- `AWMService.Frontend/apps/student/vite.config.js`: порт `3001`.
- `AWMService.Frontend/apps/universal/vite.config.js`: порт `3002`.
- `AWMService.Frontend/apps/department/vite.config.js`: порт `3003`.
- `AWMService.Frontend/apps/admin/vite.config.js`: порт `3004`.

**Решение:**
- Расширить CORS через конфигурацию, а не хардкод.
- Добавить frontend `.env` с `VITE_API_BASE_URL`.
- Зафиксировать единый base URL для всех apps.

## Этап 6. Localization Contract [DONE]
**Тема проблемы:** frontend ожидает `{ ru, kk, en }`, а backend DTO часто возвращает `TitleRu/TitleKz/TitleEn`.

**Файлы и их проблемы:**
- `AWM.Service/src/AWM.Service.WebAPI/Common/Contracts/Responses/Thesis/TopicResponse.cs`: плоские поля `TitleRu`, `TitleKz`, `TitleEn`.
- `AWM.Service/src/AWM.Service.WebAPI/Common/Contracts/Responses/Thesis/DirectionResponse.cs`: плоские поля локализации.
- `AWM.Service/src/AWM.Service.Domain/Primitives/MultilingualText.cs`: внутри использует `Kz`, frontend публично использует `kk`.
- `AWMService.Frontend/packages/shared/src/i18n/index.js`: уже поддерживает `kk/kz` fallback.

**Решение:**
- Добавить `LocalizedTextResponse { ru, kk, en }`.
- Отдавать новые поля `title`, `description`, `name` additive-способом.
- Frontend adapters должны поддерживать и новый формат, и legacy `TitleRu/TitleKz/TitleEn` до полного перехода.

## Этап 7. Error Contract [DONE]
**Тема проблемы:** ошибки приходят в разных форматах и не всегда пригодны для UI.

**Файлы и их проблемы:**
- `AWM.Service/src/AWM.Service.WebAPI/Controllers/BaseController.cs`: возвращает `{ Code, Message }`.
- `AWM.Service/src/AWM.Service.WebAPI/Common/Middleware/GlobalExceptionHandler.cs`: возвращает `ProblemDetails` без стабильного `code`.
- Frontend API слой отсутствует, поэтому ошибки будут обрабатываться на каждой странице по-разному.

**Решение:**
- Нормализовать ошибку до `ProblemDetails + code + traceId + validationErrors`.
- Frontend `apiClient` должен показывать user-safe messages.
- Единообразно обработать 401, 403, 409, validation errors.

  - notifications read.

  - frontend adapters принимают старые `TitleRu/TitleKz/TitleEn`;
  - frontend adapters принимают новые `{ ru, kk, en }`;
  - `kk` является публичным кодом казахского языка.
- Regression checks:
  - CORS для `3001-3004`;
  - refresh-token flow;
  - 401 logout;
  - 403 route denial;
  - 409 business conflicts.

## Assumptions
- `integration_plan.txt` является краткой картой.
- `modular_integration_plan.txt` является основным подробным планом.
- `kk` является публичным frontend/API кодом казахского языка; backend `Kz` остается внутренним legacy naming и маппится наружу как `kk`.
- Для frontend data fetching добавляются `axios` и `@tanstack/react-query` в shared package.
- `apps/legacy` не интегрируется в первом проходе.
