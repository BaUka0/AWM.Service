# Воркфлоу AWM — Версия 3

> **Ключевое изменение от версии 2**: Монолитный этап «Утверждение периодов Предзащит, проверок и защиты» разделён на два самостоятельных этапа:
> - **Этап 7** — Утверждение периодов Предзащит и комиссий
> - **Этап 8** — Назначение экспертов и утверждение периода защиты
>
> **Конфигурируемость под Speciality**: Все этапы воркфлоу поддерживают механизм override — кафедра задаёт общие настройки (периоды, комиссии, эксперты), а при необходимости может переопределить их для конкретной специальности. Если `SpecialityId = null` — настройки применяются ко всей кафедре; если указан — только к данной специальности.

---

## 1. Этап: Утверждение Научных Руководителей

### Действия Кафедры

**Формирование состава НР:**
1. Заходит на страницу **«Научные Руководители»**
2. Нажимает кнопку **«Добавить Научного Руководителя»**
3. В модальном окне видит список всех преподавателей кафедры с информацией:
   - ФИО полностью
   - Должность
   - Учёная степень
4. Отмечает нужных преподавателей
5. Нажимает **«Готово»**

**Утверждение состава:**
1. Проверяет финальный список выбранных НР
2. Нажимает кнопку **«Утвердить состав НР»**

**Система автоматически:**
- Отправляет уведомления преподавателям об их назначении научными руководителями
- Предоставляет НР доступ к соответствующим разделам системы

---

## 2. Этап: Утверждение периодов формирования направлений, тем, выбора тем студентами

### Действия Кафедры

1. Заходит на страницу **«Периоды и сроки»**
2. Если есть несколько специальностей — выбирает scope:
   - **«Общее для кафедры»** — применяется ко всем специальностям по умолчанию
   - **Конкретная специальность** — override для выбранной специальности
3. Устанавливает периоды для основных этапов:
   - **Для формирования направлений ДП/ДР:**
     - Поле «С» — нажимает, выбирает дату начала в календаре
     - Поле «По» — нажимает, выбирает дату окончания в календаре
   - **Для формирования тем ДП/ДР:**
     - Поле «С» — дата начала периода подачи тем
     - Поле «По» — дата окончания периода подачи тем
   - **Для выбора тем студентами:**
     - Поле «С» — дата начала выбора тем студентами
     - Поле «По» — дата окончания выбора тем студентами
4. Нажимает кнопку **«Утвердить периоды»**

> **Speciality override**: Если для специальности задан свой период — он приоритетнее. Если нет — применяется общий период кафедры.

**Система автоматически:**
- Уведомляет НР о начале периода подачи направлений и тем
- Уведомляет студентов о сроках выбора тем
- Блокирует возможность подачи заявок вне установленных периодов
- При наличии override учитывает разные периоды для разных специальностей

## 3. Этап: Формирование направлений ДП/ДР

### Действия Научного Руководителя

**Создание нового направления:**
1. Заходит на страницу **«Мои направления»**
2. Нажимает кнопку **«Создать направление»**
3. В модальном окне заполняет:
   - Название направления (на казахском, русском, английском языках)
   - Описание направления (детальное описание области исследования)
4. Нажимает **«Сохранить»**

**Отправка на рассмотрение:**
1. Проверяет заполненную информацию
2. Нажимает **«Отправить на кафедру»**

**Отслеживание статуса направления:**
- **«На рассмотрении»** — направление передано на кафедру
- **«Утверждено»** — направление принято кафедрой
- **«Отклонено»** — направление отклонено с указанием причин
- **«Требует доработки»** — необходимы исправления (выделяется ярким цветом)

### Действия Кафедры

1. Заходит на страницу **«Направления ДП/ДР»**
2. Использует фильтры по статусам:
   - На рассмотрении (приоритетная вкладка)
   - Утверждено
   - Отклонено
   - Требует доработки
3. Рассматривает каждое направление:
   - Нажимает на направление для детального просмотра
   - В модальном окне видит:
     - Полную информацию о направлении
     - ФИО и данные НР
     - Кнопки действий: **«Утвердить»**, **«Отклонить»**, **«Требует доработки»**
4. Принимает решение:
   - **«Утвердить»** — направление становится доступным для создания тем
   - **«Отклонить»** — направление отклоняется окончательно
   - **«Требует доработки»** — открывается поле для комментария с замечаниями

**При отправке на доработку:**
1. Вводит подробный комментарий с указанием необходимых исправлений
2. Нажимает **«Отправить на доработку»**

**Система автоматически:**
- Уведомляет НР о статусе рассмотрения направления
- При утверждении направления предоставляет НР возможность создавать темы

## 4. Этап: Формирование Тем ДП/ДР

### Действия Научного Руководителя

1. Заходит на страницу **«Мои темы»**
2. Выбирает утверждённое направление из выпадающего списка

**Создание темы:**
1. Нажимает кнопку **«Создать тему»**
2. В модальном окне заполняет:
   - Направление (автоматически выбранное или из списка утверждённых)
   - Название темы (на казахском, русском, английском языках)
   - Описание темы (подробное описание задач и целей)
   - Тип работы
   - Количество участников (1 — индивидуальная, 2–3 — командная)
3. Нажимает **«Сохранить тему»**

**Управление темами:**
- Видит список всех созданных тем с их статусами
- Может редактировать темы до их утверждения кафедрой
- Может создавать несколько тем в рамках одного направления

**Система автоматически:**
- Сохраняет темы в статусе «Черновик»
- Предоставляет возможность предварительного просмотра темы
- После сохранения всех тем НР может отправить их на утверждение кафедры пакетно

## 5. Этап: Выбор тем Студентами

### Действия Студента

1. Заходит на страницу **«Выбор темы ДП/ДР»**

**Просмотр доступных тем:**
- Видит все утверждённые кафедрой темы
- Использует фильтры:
  - По типу работы (ДП/ДР)
  - По направлению
  - По НР
  - По количеству участников (индивидуальная/командная)

**Изучение деталей темы:**
1. Нажимает на интересующую тему
2. В модальном окне видит:
   - Полное описание темы
   - Информацию о НР (ФИО, должность, контакты)
   - Требуемые навыки
   - Ожидаемые результаты
   - Количество свободных мест (для командных тем)
   - Кнопку **«Подать заявку»**

**Подача заявки:**
1. Нажимает **«Подать заявку»**
2. Заполняет мотивационное письмо (опционально)
3. Подтверждает подачу заявки

**Отслеживание статуса заявки:**
- **«Подана»** — заявка отправлена НР
- **«Принята»** — НР одобрил заявку
- **«Отклонена»** — НР отклонил заявку с указанием причин

### Действия Научного Руководителя

1. Заходит на страницу **«Заявки студентов»**

**Просмотр поступивших заявок:**
- Видит список заявок с информацией:
  - Тема работы
  - ФИО студента
  - Группа/курс студента
  - Мотивационное письмо (если заполнено)
  - Дата подачи заявки
  - Кнопки: **«Принять»**, **«Отклонить»**

**Принятие решений по заявкам:**
- **«Принять»** — студент закрепляется за темой
- **«Отклонить»** — заявка отклоняется с возможностью указать причину

**Управление распределением:**
- Видит количество принятых заявок по каждой теме
- Может закрыть тему при достижении лимита участников
- Получает уведомления о новых заявках

**Система автоматически:**
- Блокирует возможность подачи заявок на закрытые темы
- Уведомляет студентов о решении НР по их заявкам
- Ведёт статистику по заявкам и их статусам

## 6. Этап: Согласование тем

### Действия Кафедры

1. Заходит на страницу **«Согласование тем»**

**Сводная информация:**
- Общее количество поданных тем по направлениям
- Количество принятых заявок студентов
- Темы без заявок студентов
- Темы с превышением лимита заявок

**Массовое согласование:**
1. Использует фильтры для группировки тем:
   - По НР
   - По направлениям
   - По статусу заявок
2. Выбирает темы для массового утверждения (чекбоксы)
3. Нажимает **«Утвердить выбранные темы»**

**Обработка проблемных случаев:**
- Темы без студентов — помечает как «Неактуальные»
- Темы с избытком заявок — направляет НР для окончательного выбора
- Темы, требующие доработки — отправляет с комментариями

**Завершение этапа согласования:**
1. Нажимает **«Завершить согласование тем»**
2. Система формирует финальный список утверждённых тем с закреплёнными студентами

**Система автоматически:**
- Уведомляет всех участников об итогах согласования
- Блокирует возможность изменения состава участников по темам
- Переводит процесс к следующему этапу

## 7. Этап: Утверждение периодов Предзащит и комиссий

> **Новый самостоятельный этап** (ранее часть монолитного этапа).  
> Настраиваются **только** предзащиты (1, 2, 3) и комиссии для них.  
> Экспертные проверки и защита — отдельный следующий этап.

### 7.1. Настройка периодов предзащит

#### Действия Кафедры

1. Заходит на страницу **«Периоды предзащит»**
2. Выбирает scope настройки:
   - **«Общее для кафедры»** — настройки по умолчанию для всех специальностей
   - **Конкретная специальность** — override для выбранной специальности

**Установка периодов:**

| Предзащита | Назначение | Поля |
|------------|------------|------|
| **Предзащита 1** | Ознакомительная/тестовая. Студенты знакомятся с процедурой защиты, получают обратную связь. Без последствий для допуска. | «С» — дата начала, «По» — дата окончания |
| **Предзащита 2** | Решающая. Комиссия принимает решение о допуске/недопуске студента к защите. | «С» — дата начала, «По» — дата окончания |
| **Предзащита 3** | Пересдача. Для студентов, не явившихся или провалившихся на предыдущих предзащитах. | «С» — дата начала, «По» — дата окончания |

> **Speciality override**: Для каждой специальности кафедра может задать свои даты предзащит. Если override не задан — применяются общие даты кафедры. Это позволяет, например, провести предзащиты по ИТ-специальностям раньше, чем по другим.

3. Нажимает **«Сохранить периоды»**

### 7.2. Создание комиссий предзащит

#### Действия Кафедры

1. Нажимает **«Создать комиссию предзащиты»**
2. В модальном окне:
   - **Привязка**: выбирает специальность (или «Общая для кафедры»)
   - **Тип предзащиты**: выбирает, для какой предзащиты создаётся (1 / 2 / 3)
   - **Название комиссии** (автоматически: «Комиссия предзащиты №1 — [Специальность]»)
   - **Председатель** — выбирает из списка преподавателей кафедры
   - **Члены комиссии** — выбирает преподавателей (чекбоксы, минимум 2, максимум 4)
   - **Секретарь** — назначает технического секретаря
3. Нажимает **«Создать комиссию»**
4. Повторяет для создания нескольких комиссий при необходимости

> **Гибкость**: Одна комиссия может использоваться для нескольких предзащит. Или кафедра может создать разные комиссии для Предзащиты 1, 2 и 3. Также комиссии могут быть разными для разных специальностей.

### 7.3. Распределение студентов по комиссиям

#### Действия Кафедры

1. Видит список всех студентов с утверждёнными темами (с фильтрацией по специальности)

**Автоматическое распределение:**
1. Нажимает **«Автоматически распределить студентов»**
2. Система равномерно распределяет студентов по созданным комиссиям
3. Учитывает:
   - Специальность студента → привязка к соответствующей комиссии
   - Загруженность комиссий
   - Расписание преподавателей

**Ручная корректировка (при необходимости):**
- Перетаскивает студентов между группами
- Изменяет состав групп

### 7.4. Составление расписания предзащит

#### Действия Кафедры

Для каждой группы студентов:
1. Выбирает дату в пределах утверждённого периода (учитывая override по специальности)
2. Устанавливает время начала (например, 10:00)
3. Указывает кабинет или Teams-ссылку
4. Назначает комиссию
5. Система автоматически создаёт временные слоты (по 30 минут на студента/команду)

### 7.5. Утверждение

#### Действия Кафедры

1. Проверяет корректность всех данных:
   - Периоды предзащит (общие + override по специальностям)
   - Составы комиссий
   - Распределение студентов
   - Расписание
2. Нажимает **«Утвердить периоды и комиссии предзащит»**

**Система автоматически:**
- Уведомляет студентов о расписании предзащит (с учётом их специальности)
- Уведомляет членов комиссий об их назначении
- Создаёт календарные события для всех участников

## 8. Этап: Предзащиты

### 8.1. Предзащита 1 (ознакомительная)

> **Цель**: Студенты знакомятся с процедурой защиты, получают обратную связь от комиссии. Результаты носят **информативный характер** и **не влияют на допуск**.

#### Действия Студента

**Подготовка материалов:**
1. Заходит на страницу **«Моя предзащита»**
2. Видит информацию о предстоящей предзащите:
   - Дата и время
   - Состав комиссии
   - Кабинет/Teams-ссылка
   - Требования к материалам

**Загрузка материалов:**
1. Нажимает **«Загрузить материалы для предзащиты 1»**
2. Загружает файлы:
   - Презентация (PowerPoint/PDF)
   - Черновик ДП/ДР (текущая версия работы)
   - Дополнительные материалы (при наличии)
3. Нажимает **«Подтвердить загрузку»**

**Участие в предзащите:**
- Приходит на предзащиту в назначенное время
- Проводит презентацию работы
- Отвечает на вопросы комиссии

#### Действия Членов комиссии

**Подготовка к оценке:**
1. Заходят на страницу **«Предзащиты»**
2. Просматривают список назначенных студентов на текущий день
3. Скачивают и изучают загруженные материалы

**Процесс оценивания:**
1. Во время предзащиты каждый член комиссии заполняет оценочный лист
2. После презентации заходят в систему
3. Нажимают **«Оценить студента»** напротив соответствующего студента

**Заполнение оценок:**
- В форме оценивания заполняют критерии:
  - Актуальность темы (1–10 баллов)
  - Проработанность материала (1–10 баллов)
  - Качество презентации (1–10 баллов)
  - Ответы на вопросы (1–10 баллов)
- Система автоматически рассчитывает итоговый балл
- Вводят комментарии/замечания в текстовое поле
- Нажимают **«Сохранить оценку»**

#### Действия Секретаря комиссии

**Координация процесса:**
- Следит за ходом предзащиты
- Контролирует заполнение оценок всеми членами комиссии

**Предварительное согласование:**
1. После оценки всех студентов в сессии видит сводку оценок
2. Нажимает **«Предварительное согласование»**
3. Все члены комиссии получают уведомление и видят итоговые оценки других членов
4. Члены комиссии могут пересмотреть и изменить свои оценки

**Окончательное согласование:**
1. После обсуждения нажимает **«Окончательное согласование»**
2. Все оценки и комментарии фиксируются окончательно
3. Система формирует ведомость предзащиты 1

**Формирование ведомости:**
1. Нажимает **«Сформировать ведомость»**
2. Скачивает ведомость в PDF-формате
3. Распечатывает для подписей членов комиссии

> **Важно**: Результаты Предзащиты 1 носят рекомендательный характер. Студент получает обратную связь и замечания, но даже при низких оценках не теряет допуск к Предзащите 2.

---

### 8.2. Предзащита 2 (решающая)

> **Цель**: Комиссия принимает **решение о допуске** студента к этапу проверок и защите. Это ключевая предзащита.

Процесс аналогичен Предзащите 1 с особенностями:

#### Действия Студента
- Загружает **доработанные** материалы с учётом замечаний Предзащиты 1
- Демонстрирует исправления и доработки

#### Действия Комиссии
- Оценивают степень устранения замечаний Предзащиты 1
- Учитывают прогресс в работе при выставлении оценок
- **Принимают решение о допуске:**
  - **«Допущен»** — студент переходит к этапу проверок
  - **«Не допущен»** — студент направляется на Предзащиту 3 (пересдачу)

**Система автоматически:**
- Формирует список допущенных и недопущенных студентов
- Уведомляет недопущенных студентов о необходимости пересдачи
- Уведомляет НР о результатах
- Блокирует переход к проверкам для недопущенных студентов

---

### 8.3. Предзащита 3 (пересдача)

> **Цель**: Повторная возможность для студентов, не явившихся или не прошедших предыдущие предзащиты.

#### Условия направления на Предзащиту 3
- Студенты с решением **«Не допущен»** по результатам Предзащиты 2
- Студенты, **не явившиеся** на Предзащиту 1 или 2
- Студенты с серьёзными замечаниями комиссии

#### Действия Кафедры

**Анализ результатов:**
1. Заходит на страницу **«Результаты предзащит»**
2. Получает автоматически сформированный список студентов, направленных на пересдачу

**Корректировка периода (при необходимости):**
- Если период Предзащиты 3 был установлен ранее (этап 7) — проверяет актуальность
- При необходимости корректирует даты, комиссию
- Нажимает **«Обновить настройки пересдачи»**

#### Действия Студента
- Загружает существенно доработанные материалы
- Демонстрирует полное устранение замечаний

#### Действия Комиссии
- Оценивают полноту устранения замечаний
- Принимают окончательное решение о допуске:
  - **«Допущен»** — студент переходит к проверкам
  - **«Не допущен окончательно»** — студент не допускается к защите в текущем семестре

**Система автоматически:**
- Ведёт учёт количества попыток сдачи каждого студента
- Формирует отчёты по успеваемости для кафедры
- Блокирует переход к следующему этапу для студентов, не сдавших предзащиту

---

## 9. Этап: Назначение экспертов и утверждение периода защиты

> **Новый самостоятельный этап** (ранее часть монолитного этапа).  
> Настраиваются экспертные проверки (нормоконтроль, ПО, антиплагиат, рецензенты) и период защиты.  
> Этот этап проводится **после** завершения предзащит, когда известен список допущенных студентов.

### 9.1. Назначение экспертов

#### Действия Кафедры

1. Заходит на страницу **«Эксперты и проверки»**
2. Выбирает scope настройки:
   - **«Общее для кафедры»** — эксперты по умолчанию для всех специальностей
   - **Конкретная специальность** — override для выбранной специальности

**Добавление экспертов:**

| Тип проверки | Назначение | Количество |
|-------------|------------|------------|
| **Нормоконтроль** | Проверка оформления ДП/ДР | Один или несколько преподавателей кафедры |
| **Проверка ПО** | Техническая проверка кода и ПО | Один или несколько преподавателей кафедры |
| **Антиплагиат** | Проверка оригинальности текста | Один или несколько ответственных |
| **Рецензенты** | Внешняя рецензия на работу | Добавляются отдельно (см. ниже) |

**Добавление рецензентов:**
1. Нажимает **«Добавить рецензента»**
2. Заполняет данные:
   - ФИО полностью
   - Должность и учёная степень
   - Университет/организация
   - Контактная информация
3. Привязывает рецензента к конкретным студентам или специальностям

### 9.2. Установка периода проверок

#### Действия Кафедры

1. Устанавливает общий период проведения проверок:
   - **Период проверок:**
     - Поле «С» — дата начала периода проверок
     - Поле «По» — дата окончания периода проверок
2. При необходимости — override для конкретной специальности

### 9.3. Настройка периода защиты

#### Действия Кафедры

1. Устанавливает период защиты:
   - **Защита ДП/ДР:**
     - Поле «С» — дата начала периода защиты
     - Поле «По» — дата окончания периода защиты
2. Этот период используется для информирования студентов о сроках подготовки
3. При необходимости — override для конкретной специальности

### 9.4. Утверждение

#### Действия Кафедры

1. Проверяет корректность всех данных:
   - Назначенные эксперты (общие + override по специальностям)
   - Привязки рецензентов
   - Периоды проверок и защиты
2. Нажимает **«Утвердить экспертов и периоды»**

**Система автоматически:**
- Уведомляет экспертов о назначении на проверки
- Уведомляет рецензентов о назначении
- Уведомляет студентов о сроках проверок и защиты
- Создаёт календарные события для всех участников

---

## 10. Этап: Проверки

### 10.1. Нормоконтроль

#### Действия Студента

**Подготовка к проверке:**
1. Заходит на страницу **«Мои проверки»**
2. Видит статус: «Нормоконтроль — Ожидает загрузки материалов»

**Загрузка материалов:**
1. Нажимает **«Загрузить материалы для нормоконтроля»**
2. Загружает финальную версию ДП/ДР в формате Word/PDF
3. Заполняет сопроводительную информацию
4. Нажимает **«Отправить на проверку»**

**Ожидание результатов:**
- Отслеживает статус проверки в личном кабинете
- Получает уведомления об изменении статуса

#### Действия Эксперта по нормоконтролю

**Получение материалов:**
1. Заходит на страницу **«Мои проверки — Нормоконтроль»**
2. Видит список работ, поступивших на проверку
3. Скачивает материалы для анализа

**Проведение проверки:**
- Проверяет соответствие требованиям оформления:
  - Титульный лист
  - Содержание
  - Форматирование текста
  - Списки литературы
  - Приложения

**Вынесение решения:**
- **Если прошёл:**
  1. Нажимает **«Зачёт»**
  2. Указывает краткий комментарий об отсутствии замечаний
- **Если не прошёл:**
  1. Нажимает **«Незачёт»**
  2. Подробно описывает все замечания в текстовом поле
  3. Может прикрепить файл с разметкой замечаний

**Отправка результатов:**
- Нажимает **«Отправить результат студенту»**

**Цикл доработки (при незачёте):**
1. Студент получает замечания, дорабатывает материалы, повторно загружает
2. Эксперт повторно проверяет исправления
3. Цикл повторяется до получения зачёта
4. При зачёте: система блокирует возможность студента загружать новые версии

---

### 10.2. Проверка ПО

#### Действия Студента

**Подготовка материалов:**
1. Заходит на страницу **«Мои проверки»**
2. Нажимает **«Подготовить материалы для проверки ПО»**

**Предоставление доступа к коду:**
- **GitHub-репозиторий:**
  - Вводит ссылку на публичный репозиторий
  - Или добавляет эксперта в приватный репозиторий
- **Архив проекта:**
  - Загружает ZIP-архив с исходным кодом
  - Добавляет README с инструкциями по запуску

**Дополнительная информация:**
1. Заполняет техническое описание:
   - Используемые технологии
   - Требования к системе
   - Инструкции по установке и запуску
2. Нажимает **«Отправить на проверку ПО»**

#### Действия Эксперта по проверке ПО

**Получение материалов:**
1. Заходит на страницу **«Мои проверки — ПО»**
2. Открывает ссылку на GitHub или скачивает архив

**Техническая проверка:**
- Анализирует структуру проекта
- Проверяет качество кода
- Тестирует функциональность
- Проверяет соответствие техническим требованиям

**Документирование результатов:**
- **Если прошёл:**
  1. Нажимает **«Зачёт»**
  2. Указывает положительные моменты
- **Если не прошёл:**
  1. Нажимает **«Незачёт»**
  2. Детально описывает технические замечания
  3. Указывает конкретные требования к доработке

---

### 10.3. Антиплагиат

#### Действия Системы (автоматически)
- Передаёт на проверку антиплагиата только материалы, **прошедшие нормоконтроль**
- Уведомляет эксперта по антиплагиату о поступлении новых материалов

#### Действия Эксперта по антиплагиату

**Получение материалов:**
1. Заходит на страницу **«Мои проверки — Антиплагиат»**
2. Видит список работ, прошедших нормоконтроль
3. Скачивает материалы для проверки

**Проведение проверки:**
1. Загружает материалы в систему антиплагиата
2. Анализирует результаты проверки
3. Определяет процент оригинальности

**Оформление результатов:**
1. Заполняет форму с результатами:
   - Процент оригинальности (числовое поле)
   - Комментарии и замечания (текстовое поле)
2. Генерирует официальный документ с подписью и печатью
3. Загружает подписанный документ в систему

**Вынесение решения:**
- **Если процент выше порогового:**
  1. Нажимает **«Зачёт»**
  2. Студенту блокируется возможность изменения материалов
- **Если процент ниже порогового:**
  1. Нажимает **«Незачёт»**
  2. Указывает требования к доработке

**Цикл доработки при незачёте:**
1. Студент дорабатывает материалы
2. Повторно проходит нормоконтроль
3. Затем снова антиплагиат
4. Проверку ПО повторно проходить **не требуется**
5. Цикл продолжается до достижения порогового процента

---

### 10.4. Рецензия

#### Действия Студента

**Подготовка материалов для рецензента:**
1. Заходит на страницу **«Моя рецензия»**
2. Видит контактную информацию назначенного рецензента
3. Скачивает пакет документов для отправки:
   - Финальная версия ДП/ДР
   - Отзыв научного руководителя
   - Справка о прохождении нормоконтроля
   - Справка о прохождении проверки ПО
   - Документ результатов антиплагиата с подписью и печатью

**Отправка материалов рецензенту:**
1. Отправляет все материалы рецензенту по указанной электронной почте
2. В теме письма указывает: «Материалы для рецензирования — [ФИО студента] — [Тема работы]»
3. Подтверждает отправку в системе, нажав **«Материалы отправлены рецензенту»**

**Получение рецензии:**
1. Получает от рецензента отзыв с подписью и печатью
2. Заходит на страницу **«Моя рецензия»**
3. Нажимает **«Загрузить рецензию»**
4. Загружает отсканированный документ рецензии
5. Нажимает **«Подтвердить загрузку рецензии»**

#### Действия Рецензента
- Получает материалы по электронной почте
- Изучает предоставленные документы
- Составляет письменную рецензию
- Подписывает и заверяет печатью рецензию
- Отправляет рецензию студенту

#### Контроль Кафедры
- Отслеживает статус получения рецензий
- При необходимости напоминает студентам о сроках
- Контролирует качество загруженных рецензий

---

## 11. Этап: Подготовка к защите

### Действия Кафедры

**Анализ готовности студентов:**
1. Заходит на страницу **«Готовность к защите»**
2. Видит список всех студентов со статусами по этапам:
   - ✅ Предзащиты пройдены
   - ✅ Нормоконтроль пройден
   - ✅ Проверка ПО пройдена
   - ✅ Антиплагиат пройден
   - ✅ Рецензия получена
3. Использует фильтры для просмотра:
   - Готовые к защите
   - Незавершённые этапы
   - Критические задержки

**Работа с неготовыми студентами:**
1. Выбирает студентов с незавершёнными этапами
2. Нажимает **«Отправить уведомления»**
3. Система автоматически отправляет персонализированные уведомления:
   - Студентам — о незавершённых этапах
   - НР — о студентах с задержками
   - Экспертам — о pending-проверках

**Формирование списка допущенных:**
1. После завершения всех этапов студентами
2. Нажимает **«Сформировать список допущенных к защите»**
3. Система автоматически генерирует документ со списком
4. Скачивает документ в PDF-формате для официального оформления

**Создание комиссии ГАК:**
1. Нажимает **«Создать комиссию ГАК»**
2. В модальном окне заполняет:
   - **Председатель ГАК** (приглашённый специалист):
     - ФИО полностью
     - Должность и учёная степень
     - Университет/организация
     - Контактная информация
   - **Заместитель председателя** (из штатных преподавателей)
   - **Члены комиссии** (выбирает 3–5 преподавателей кафедры)
   - **Секретарь комиссии** (технический секретарь)
3. При необходимости — отдельные комиссии ГАК для разных специальностей

**Составление расписания защиты:**
1. Устанавливает даты защиты в пределах утверждённого периода (из этапа 9)
2. Для каждого дня защиты:
   - Выбирает состав комиссии (если несколько комиссий)
   - Указывает аудиторию
   - Создаёт временные слоты (по 45 минут на защиту)
   - Распределяет студентов по слотам

**Утверждение расписания:**
1. Проверяет корректность расписания
2. Нажимает **«Утвердить расписание защиты»**

**Система автоматически:**
- Уведомляет студентов о дате, времени и составе комиссии
- Уведомляет членов комиссии ГАК об их назначении
- Создаёт календарные события для всех участников
- Формирует пакеты документов для каждого члена комиссии

---

## 12. Этап: Защита

### Действия Студента

**Подготовка к защите:**
1. Заходит на страницу **«Моя защита»**
2. Видит информацию о защите:
   - Дата и время
   - Состав комиссии ГАК
   - Аудитория
   - Регламент выступления (20–25 минут общее время)

**Загрузка материалов для защиты:**
1. Нажимает **«Загрузить материалы для защиты»**
2. Загружает файлы:
   - Презентация (PowerPoint/PDF)
   - Демонстрационные материалы (видео, скриншоты ПО)
   - Раздаточный материал (при наличии)
3. Нажимает **«Подтвердить загрузку»**

**Участие в защите:**
- Приходит на защиту в назначенное время
- Проводит презентацию работы (10–15 минут)
- Отвечает на вопросы комиссии (10–15 минут)
- Отвечает на замечания рецензента (5 минут)

### Действия Членов комиссии ГАК

**Подготовка к оценке:**
1. Заходят на страницу **«Защиты ГАК»**
2. Просматривают список назначенных студентов на текущий день
3. Скачивают и изучают материалы студентов:
   - Дипломная работа/проект
   - Отзыв научного руководителя
   - Рецензия
   - Справки о прохождении всех проверок

**Процесс оценивания:**
1. Во время защиты каждый член комиссии заполняет оценочный лист
2. После презентации заходят в систему
3. Нажимают **«Оценить защиту»** напротив соответствующего студента

**Заполнение оценок:**
- В форме оценивания заполняют критерии:
  - Актуальность и новизна работы (1–10 баллов)
  - Теоретическая проработанность (1–10 баллов)
  - Практическая значимость (1–10 баллов)
  - Качество презентации (1–10 баллов)
  - Ответы на вопросы (1–10 баллов)
  - Общая оценка (отлично/хорошо/удовлетворительно/неудовлетворительно)
- Система автоматически рассчитывает средний балл
- Вводят комментарии и замечания в текстовое поле
- Нажимают **«Сохранить оценку»**

### Действия Секретаря комиссии ГАК

**Координация процесса:**
- Ведёт протокол защиты
- Следит за ходом защиты и соблюдением регламента
- Контролирует заполнение оценок всеми членами комиссии

**Предварительное согласование:**
1. После защиты всех студентов в сессии видит сводку оценок
2. Нажимает **«Предварительное согласование»**
3. Все члены комиссии получают уведомление и видят итоговые оценки других членов
4. Члены комиссии могут пересмотреть и изменить свои оценки

**Окончательное согласование:**
1. После обсуждения нажимает **«Окончательное согласование»**
2. Все оценки и комментарии фиксируются окончательно
3. Система формирует итоговую ведомость защиты

**Формирование документов:**
1. Нажимает **«Сформировать ведомость»**
2. Скачивает ведомость защиты в PDF-формате
3. Распечатывает для подписей всех членов комиссии ГАК

**Система автоматически:**
- Уведомляет студентов о результатах защиты
- Формирует итоговые документы и справки
- Ведёт статистику по результатам защиты
- Архивирует все материалы по дипломным работам
- Переводит успешно защитившихся студентов в статус «Выпускник»

---

## Завершение процесса

- Кафедра получает сводный отчёт по защите
- Формируется список выпускников с указанием итоговых оценок
- Система переходит в архивный режим для данного учебного года
- Подготавливается к новому циклу дипломного проектирования
